## Подготовка среды

### Windows

1. Скачать **Docker Desktop** с [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/).
2. При установке выбрать **WSL 2 backend** (это вариант по умолчанию, ничего трогать не надо).
3. Запустить Docker Desktop. В трее должен появиться значок-кит – должен быть «зелёным».
4. Открыть PowerShell или Windows Terminal.

### macOS

1. Скачать **Docker Desktop** с [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/). Для Apple Silicon (M1/M2/M3) – вариант **Mac with Apple chip**, для старых – **Mac with Intel chip**.
2. Перетащить в Applications, запустить.
3. Дождаться, пока значок-кит в строке меню перестанет анимироваться.

### Linux

Самый быстрый способ – установочный скрипт:

```bash
curl -fsSL https://get.docker.com | sh
```

После установки добавить себя в группу `docker`, чтобы не писать `sudo` перед каждой командой:

```bash
sudo usermod -aG docker $USER
```

**Перелогиниться** в систему (или перезагрузиться), чтобы права применились.

### Проверка установки

В терминале (PowerShell на Windows, Terminal на macOS/Linux):

```bash
docker version
```

Если выводится информация о клиенте и сервере – всё готово.

## Задание 1. Знакомство с командами Docker

Выполните последовательность команд и кратко опишите, что произошло на каждом шаге.

> Будем работать с минималистичным контейнером `traefik/whoami` – это маленький HTTP-сервер, который на любой запрос отвечает своими данными: hostname контейнера, его IP, заголовки запроса.

### Шаг 1. Версия и информация о системе

```bash
docker version
docker info
```

`docker version` показывает версии клиента и демона. `docker info` выводит детальную информацию о состоянии Docker: сколько образов, сколько контейнеров, какой драйвер хранения, сколько памяти доступно демону.

### Шаг 2. Первый запуск

```bash
docker run hello-world
```

Контейнер скачивается, запускается, выводит приветственное сообщение и тут же завершается. Прочитайте вывод – там описано, что именно произошло.

### Шаг 3. Запустить веб-сервис в фоне

```bash
docker run -d --name demo -p 8080:80 traefik/whoami
```

Разбор ключей:

- `-d` – запустить в фоне (`detached`), не блокировать терминал;
- `--name demo` – дать контейнеру имя `demo` вместо случайной строки;
- `-p 8080:80` – пробросить порт 80 контейнера на порт 8080 хоста;
- `traefik/whoami` – имя образа.

Откройте в браузере `http://localhost:8080`. Вы увидите что-то вроде:

```
Hostname: 9f8a7b6c5d4e
IP: 172.17.0.2
RemoteAddr: 172.17.0.1:54322
GET / HTTP/1.1
Host: localhost:8080
User-Agent: ...
```

Запомните значение `Hostname` – оно пригодится на шаге 6.

### Шаг 4. Посмотреть запущенные контейнеры

```bash
docker ps
```

В выводе должен быть контейнер `demo`, статус `Up`, проброс портов `0.0.0.0:8080->80/tcp`.

Чтобы увидеть **все** контейнеры (включая остановленные), добавьте `-a`:

```bash
docker ps -a
```

### Шаг 5. Логи контейнера

```bash
docker logs demo
```

Видно, как сервис стартовал и обработал ваш запрос из шага 3 (если успели зайти в браузер).

Чтобы смотреть логи в реальном времени, как `tail -f`:

```bash
docker logs -f demo
```

(`Ctrl+C` – выйти из режима слежения.)

### Шаг 6. Заглянуть внутрь контейнера

`traefik/whoami` – минималистичный образ без shell, поэтому `docker exec` не сработает. Информацию о контейнере получаем через `docker inspect`:

```bash
docker inspect -f '{{.Config.Hostname}}' demo
docker inspect -f '{{.NetworkSettings.IPAddress}}' demo
```

Чтобы увидеть процесс контейнера со стороны хоста:

```bash
ps aux | grep whoami
```

**Обратите внимание:**

- `Hostname` из вывода `inspect` совпадает с тем, что вы видели в браузере – это UTS namespace в действии: у контейнера своё имя хоста, изолированное от системы;
- `ps aux | grep whoami` на хосте показывает процесс, но с другим PID, чем внутри контейнера – PID namespace даёт контейнеру собственное пространство идентификаторов процессов;
- файловая система контейнера изолирована от хостовой через MNT namespace – внутри виден свой `/`, не ваш диск.

### Шаг 7. Потребление ресурсов

```bash
docker stats --no-stream
```

Покажет, сколько CPU и памяти потребляет каждый контейнер. Без `--no-stream` – вывод обновляется в реальном времени (`Ctrl+C` – выйти).

### Шаг 8. Параметры контейнера

```bash
docker inspect demo
```

Огромная JSON-структура: IP-адрес внутри docker-сети, переменные окружения, точки монтирования, конфигурация сети, состояние процесса.

Чтобы вытащить конкретное поле:

```bash
docker inspect -f '{{.NetworkSettings.IPAddress}}' demo
```

### Шаг 9. Остановить и запустить снова

```bash
docker stop demo
docker ps              # demo пропал из списка работающих
docker ps -a           # demo есть, но статус Exited
docker start demo
docker ps              # снова работает
```

Контейнер – это сохраняемая сущность. Остановленный контейнер можно запустить снова, его данные на месте.

### Шаг 10. Удалить контейнер

```bash
docker stop demo
docker rm demo
```

Чтобы не разделять стоп и удаление, есть короткая форма:

```bash
docker rm -f demo
```

### Шаг 11. Работа с образами

Посмотреть локальные образы:

```bash
docker images
```

Удалить образ:

```bash
docker rmi traefik/whoami
docker rmi hello-world
```

### Шаг 12. Уборка

Посмотреть, сколько Docker занимает места:

```bash
docker system df
```

Удалить всё неиспользуемое (контейнеры, сети, кэш сборки) одним движением:

```bash
docker system prune
```

С `-a` ещё и образы, которые не используются ни одним контейнером:

```bash
docker system prune -a
```

## Задание 2. Развернуть собственное приложение

Выберите **одно** приложение из таблицы ниже и разверните его. Все приложения запускаются одной командой и имеют веб-интерфейс.

| Приложение        | Команда запуска                                                                | Открывать        | Что это                                                                                            |
| ----------------- | ------------------------------------------------------------------------------ | ---------------- | -------------------------------------------------------------------------------------------------- |
| **Excalidraw**    | `docker run -d --name excalidraw -p 3000:80 excalidraw/excalidraw`             | `localhost:3000` | Рисовалка схем «от руки». Whiteboard, как Miro, но локальный и без аккаунта                        |
| **n8n**           | `docker run -d --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n n8nio/n8n`  | `localhost:5678` | Конструктор автоматизаций: соединяешь блоки в workflow                                             |
| **code-server**   | `docker run -d --name code -p 8443:8080 -e PASSWORD=lab9 codercom/code-server` | `localhost:8443` | VS Code прямо в браузере (пароль для входа: `lab9`)                                                |

| **PrivateBin**    | `docker run -d --name bin -p 8088:8080 privatebin/nginx-fpm-alpine`            | `localhost:8088` | Свой pastebin с шифрованием прямо в браузере                                                       |

### Что нужно сделать

1. Выбрать приложение, запустить его командой из таблицы.
2. Открыть в браузере по указанному адресу. Если приложение долго стартует – дайте ему 10–30 секунд и обновите страницу. Логи стартующего сервиса можно посмотреть через `docker logs <имя>`.
3. **Потыкать интерфейс**: что-то нарисовать / собрать workflow / отредактировать файл / посчитать хеш / измерить скорость. Минимум одно осмысленное действие.
4. Сделать **скриншот** веб-интерфейса с результатом вашей деятельности (нарисованная схема, отредактированный текст, посчитанный хеш и т.п.).
5. Зайти внутрь контейнера через `docker exec -it <имя> sh` (или `bash`, если `sh` не найдётся), посмотреть `ps` и `hostname`. Найти основной процесс приложения. Сделать скриншот.
6. Посмотреть логи через `docker logs <имя>` – что пишет приложение при работе. Сделать скриншот.
7. Остановить и удалить контейнер: `docker rm -f <имя>`.

### Что должно быть в README

- Какое приложение выбрали и почему.
- Команда запуска (можно скопировать из таблицы).
- Что вы делали внутри приложения (1–2 предложения).
- Скриншоты:
  - веб-интерфейс с вашим результатом;
  - вывод `ps` внутри контейнера;
  - первые несколько строк `docker logs`.

### Дополнительно

- Запустить **два разных** приложения из таблицы одновременно. Они должны работать на разных портах и не мешать друг другу.
- Применить лимит памяти при запуске: `--memory=256m`. Посмотреть в `docker stats`, как меняется потребление. В README – какое значение в колонке `MEM USAGE / LIMIT`.
- Контейнеры с томом (`n8n`) – после `docker rm -f n8n` и повторного запуска данные должны сохраниться. Проверить и описать.
